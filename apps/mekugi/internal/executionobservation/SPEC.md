# Execution observation

Execution observation joins prepared requests, arriving provider responses and
completed Codex tool facts with the composed capture and retained-evidence owners.
Codex owns execution, permissions and continuation. Observation preserves exact
host input and results, including failed, partial and caught tool outcomes.

Prepared-output observations decode text transport parts and compare them with
the same call or attachment in the original request. They preserve structured
non-text content and whole-cell identity without rerunning projections. Missing
evidence cannot establish altered content.

The preparer borrows invocation owners. Each prepared response retains its own
scope and dependencies through delivery and cleanup, independently of the
preparer. Frontends supply preview timing; this workflow has no renderer.

Independent-thread requests bind their authenticated host identity to Thread
Control before inference. Only the confirmed successful result of a registered
wait's enclosing execution can admit a local stop; nested MCP success alone cannot.
Prepared child preload selections bind to retained assignment identities. The
shared compaction reader completes acquisition before provider inference and
projects complete retained bodies and failed reads without exposing orchestration
calls. Prewarm and execution-free requests never start acquisition; completed
results remain reusable across continuation and resume.

One invocation window registry joins command reports and capture observations.
Native shell operations use the same admission and completion workflow, retaining
their original thread, namespace and workspace when the displayed session changes.
Restoration reads durable facts without reviving windows or capturing baselines.

History owns retained reads, snapshot leases, namespace admission and publication
transactions. Changes owns change identity and membership; Recovery owns retained
output. Cross-owner publication and input adoption use `recordtransactions`.
Storage-pressure retry retains completed facts without repeating execution or
provider inference. Startup owns maintenance and resource shutdown.

Acceptance covers exact request projection, partial delivery, cancellation,
fork/resume ancestry, immutable replay, publication failures, overlapping writers,
native-shell switching and the installed Codex consumer.
